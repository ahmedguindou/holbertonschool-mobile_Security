# Report — Task 2: Android Cryptography — Interception and Decryption

## Objective

The goal of this task was to recover a concealed flag from the Android application `app-release-task2.apk`. The application performs all cryptographic operations locally, so no communication with an external server is required.

The main challenge was identifying how the encryption key was generated and reproducing the XOR-based decryption process through static analysis.

## 1. Inspecting the Decompiled APK

The APK was first decompiled with JADX:

```bash
jadx ~/Desktop/app-release-task2.apk -d ~/Desktop/task2_jadx
```

During the source inspection, two relevant Kotlin-generated Java files were identified:

```text
com/holberton/task3/MainActivityKt.java
com/holberton/task3/MainActivity.java
```

`MainActivity.java` mainly handles the application's interface, while `MainActivityKt.java` contains the cryptographic functionality and the code responsible for recovering the hidden message.

## 2. Understanding the Decryption Mechanism

Three important methods were found in `MainActivityKt.java`.

### `performslowDecryption()`

This method contains the encrypted data and initiates the complete decoding process:

```java
public static final String performslowDecryption() {
    byte[] decoded = Base64.getDecoder().decode(
        "cVZaW1dDQllZTFdRW1xeUlBbX21CWFtHalRZXUJFRFhNX1ZcbllGQ15cUUNSRFpcVks="
    );

    return xorDecrypt(
        new String(decoded, UTF_8),

```

The encrypted value is first decoded from Base64. The resulting string is then passed to `xorDecrypt()`, together with a key generated by `slowRecursive(150)`.

### `slowRecursive(int n)`

The key-generation function is a recursive implementation of the Fibonacci sequence:

```java
public static final long slowRecursive(int i) {

```


The implementation is intentionally inefficient because each value is recalculated repeatedly. This results in exponential time complexity and makes executing the application unnecessarily slow during dynamic analysis.

The actual decryption is performed using XOR.

Conceptually, the operation is:

```text

## 5. Security Observations


First, the encryption key is not actually secret. It is generated deterministically from a value that can be obtained directly from the application's code.

Second, the recursive Fibonacci implementation is computationally inefficient. Its exponential runtime is mainly useful for slowing down someone attempting dynamic analysis, rather than providing any real cryptographic protection.

Finally, XOR encryption with a predictable repeating key is not a secure way to protect sensitive information. Once the key-generation logic is understood, the encrypted value can be reversed entirely through static analysis.
```
